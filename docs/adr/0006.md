# ADR-006：用户配置的单账号执行与真实安全边界

日期：2026-10-14。状态：用户已明确选择单一 Linux 账号，自行配置该账号。此项替代早期双 UID 提议，不创建系统账号、特权助手或修改生产权限。

## 决定

Agent 与 Exec 默认使用同一个非 root 账号，保留 ExecutionBackend 抽象，可显式禁用执行。服务端按真实平台用户、设备、任务记录命令、事件及输出；用户身份不等于 Linux UID。P2 才实现 PTY 与中央强制录像。

2026-10-15 终端补充：按用户在本地开发容器中使用 `sudo -i` 的要求，开发镜像配置容器内 sudo，启动脚本显式启用终端提权。普通部署仍默认禁止 PTY 提权；只有运维设置 `FLEET_TERMINAL_ALLOW_PRIVILEGE_ESCALATION=1` 后才采用系统现有 sudo 策略。Agent 本身及持久化 Exec 继续使用非 root 账号，Exec 的 `no_new_privs` 不放开。

## 不能忽略的边界

同 UID 的任意命令可以读取 Agent 私钥、读取或修改本地 journal/outbox、干扰输出采集，甚至冒充 Agent。chmod 0600 不能隔离同 UID。服务端已经持久化的记录不会因删除本地日志而自动消失，但中央记录不能证明受控主机上未被篡改的完整执行事实。因此这一版本不宣称端点强隔离、审计防绕过或防恶意管理员篡改。仅向可信运维授予任意 Exec。业务人员与审计员不得调用 Exec。

## 生命周期

命令采用独立进程组、清理环境、TERM→KILL、wait/reap。进程组不能约束主动 setsid/double-fork 逃逸的后代；没有受控 cgroup 时强制终止结果采用 UNKNOWN 和明确 cleanup-unconfirmed 原因，不伪称完整清理。普通 fork 后代应在 Linux 实测停止。

审计写入或输出限额异常必须停止任务并明确 audit_complete=false。服务端未确认前保留结果，已有服务器事件不覆盖。后续若需要强隔离，先与用户确认独立执行身份、受控启动器或 cgroup，不能在此版本偷偷创建。
