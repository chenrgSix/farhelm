## ADR-002：设备密钥、注册与认证

**决定：** 每设备 Ed25519 密钥、经管理员授权的一次性短 TTL 注册令牌、TLS 校验、短期设备访问令牌。签名原语使用成熟库及 [RFC 8032 测试向量](https://www.rfc-editor.org/rfc/rfc8032#section-7.1)，不自行实现密码算法。以下挑战协议是本项目设计，需要契约与攻击测试。

1. 注册令牌随机高熵，服务端仅保存摘要；绑定用途、归属和最大使用次数，P0 默认一次。核销、设备创建和审计同一事务完成，阻止并发双重兑换
2. 注册请求除 token、公钥外，必须证明持有对应私钥。签名内容使用明确的字节编码与域分隔，绑定服务实例、用途、challenge ID、随机 nonce、公钥、注册 token 摘要、到期时间；不要直接签不稳定序列化的 JSON
3. 后续认证挑战绑定 device ID、公钥版本、服务实例、用途及过期时间；至少 256-bit 随机 nonce；服务端验证后原子标记已使用，再发短期、限定 audience/scope 的 token。挑战及失败尝试限速
4. 注册响应丢失时，用原密钥证明持有权找回同一个设备身份；不得再次创建设备，也不能仅凭曾用 token 获取新凭据
5. Agent 通过 Authorization 传 token，禁止放 URL、常规日志、浏览器页面。已撤销设备关闭旧连接并拒绝新认证，长连接在授权到期时重新认证或重连
6. P0 即具备真实管理员身份与设备范围检查。开发可用显式初始化的本地管理员，不接受客户端自报 `actor_id`、默认公共密码或无需登录的执行接口。企业 SSO/MFA 接入后续确定

**故障原则：** 本地私钥/journal 丢失不能悄悄当“新安装”继续旧任务；进入需要重新授权注册的恢复流程。服务端 TLS 失败不得降级跳过校验。
