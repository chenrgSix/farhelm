## ADR-003：至少一次投递，疑似已执行绝不盲目重跑

**决定：** 任务不可变，Agent 本地持久化去重；运行状态不确定即 `UNKNOWN`。这不是通用 Shell exactly-once 保证。

执行顺序：

1. 服务端授权后，在一个事务内记录不可变请求、操作人、授权决策、任务及创建审计，然后才能发送
2. Agent 校验 task ID、设备、TTL、参数与本机策略；原子写入 `ACCEPTED` 和 accepted outbox 事件，持久化完成后再回应
3. 调度器在执行前检查 TTL、并发和取消状态；持久化 `RUNNING`/started 事件后才启动进程。此处与 OS spawn 不可能组成数据库原子事务
4. 完成后先封存输出，再原子提交结果与 finished outbox；断线只影响发送，不改变正在执行的命令
5. 重启发现 `ACCEPTED` 可按未开始任务恢复；发现 `RUNNING` 且没有可靠完成记录则先清理/核对残留进程，再标 `UNKNOWN`，不自动重启该命令。即使崩溃发生于写 RUNNING 后、spawn 前，也保守按 UNKNOWN

补充约束：

- 相同 task ID、相同不可变 payload 仅返回已有状态；相同 ID 不同 payload 拒绝并审计。使用请求哈希和唯一约束，不仅靠内存锁
- P1 每设备任务并发固定为 1，Agent 单实例锁防止两个进程同时使用同一个身份/journal；并发槽在进程清理和结果封存完成后释放
- Web 重复点击/HTTP 重试使用绑定操作人与请求内容的 idempotency key；仅在 Agent 去重仍会漏掉两个不同任务 ID 的重复操作
- `SENT` 仅表示尝试发送，丢失 accepted ACK 时只能重发同一个 ID；新连接取得唯一发送权，旧连接不能继续下发新任务
- 单纯失联显示连接丢失/等待补传，不立即把任务定为 UNKNOWN。UNKNOWN 是有执行歧义的事实；以后收到原始可信完成证据可以附加核对记录并修正展示，历史不可覆盖
- `EXPIRED` 仅指尚未开始已过 TTL；`TIMED_OUT`/`CANCELLED` 需有实际终止和清理证据，取消请求本身不是终态。无法确认终止则保留不确定性
- P1 禁止自动重试 UNKNOWN。用户确认后另建带 `retry_of` 的新任务并提示原操作可能已生效；“幂等模板自动重试”以后逐模板审核
- 去重墓碑不能随已 ACK outbox 一起删，也不能任意按短期 TTL 清理；保留范围必须覆盖服务端所有合法重投/恢复路径
