## ADR-001：单体边界与一条执行链

**决定：** 保持现有技术栈和单实例。REST `commands` 是用户入口，Agent 仅有一条持久化任务执行管线；`AGENT_EXEC` 是任务的一种，不另建绕过 journal/outbox 的 `exec.request` 快捷通道。

- `task_id` 标识一次设备执行；`job_id` 标识业务/批量请求；`execution_id` 如保留，只是审计关联，不触发第二次执行
- Agent 只主动连接；公网 WSS 始终负责控制，独立 HTTPS/流连接负责大输出、文件和 PTY。P1 就提供最小输出上传接口，私网选择策略到 P3 再实现
- 未配置 EasyTier 时 Agent 正常工作；控制在线、私网数据可达、业务健康分别建模，未采集的状态为未知，不能默认健康
- 队列由持久化任务表和单进程 scheduler 实现；内存连接表仅作连接索引，不是真实任务状态
- API 身份、Agent 身份和数据上传授权分离。设备名称、部门、用户 ID、角色不能由 Agent 上报即成为可信授权依据

**代价：** 单机仍是故障点，SQLite 不承诺 500 台持续终端满负荷性能。以 P5 实测决定是否迁移 PostgreSQL，而非预先堆基础设施。
