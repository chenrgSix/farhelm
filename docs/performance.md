# 性能验证

## 设备列表批量读取（2026-10-22）

设备列表先在 SQL 中限制用户可见范围，再批量读取分组、网络策略、健康结果和有效连接凭据。同一请求复用状态；不跨请求缓存权限或连接状态，撤销和配置变化在下一次请求生效。保持原有列表响应和全量选择语义。

本地 macOS、Node 24.21.0、临时 SQLite 数据库，真实 Fastify `/api/v1/devices` handler（inject，无网络传输），静态离线 Agent 设备。预热后取 7 次请求中位数：

| 设备数 | 优化前 SQL prepare 调用 | 优化后 | 优化前中位耗时 | 优化后 |
| --- | ---: | ---: | ---: | ---: |
| 50 | 1,255 | 13 | 5.03 ms | 0.53 ms |
| 500 | 12,505 | 13 | 47.70 ms | 2.46 ms |
| 1000 | 25,005 | 13 | 95.29 ms | 4.76 ms |

网络策略首次应用可能仍需逐设备持久化，这是原有行为；表中为无需修改策略的读取。数据不代表在线终端并发、生产硬件或端到端延迟。

`apps/server/test/device-list.test.ts` 对 500 台设备设置查询数量回归门禁，并验证授权范围变化、凭据不泄漏、分组/IP/SSH/网络策略投影及撤销状态。服务端 181 项测试、协议契约 370 项、服务端类型检查通过。
