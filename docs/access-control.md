# 访问控制与登录账号

Farhelm 将人员、操作权限、资源授权和连接凭据分开维护：

| 对象 | 职责 | 入口 |
| --- | --- | --- |
| 用户、用户组 | 平台身份和人员组织 | 访问控制 → 用户／用户组 |
| 角色 | 查看、终端连接、任务执行、sudo／特权账号等操作权限 | 访问控制 → 角色 |
| 设备、设备组 | 服务器和分类标签 | 设备总览 |
| 登录账号 | Linux 身份、直接 SSH 或 sudo 切换、托管凭据 | 设备 → 更多 → 登录账号 |
| 访问授权 | 哪些用户、组或角色可以使用哪台设备的哪些登录账号 | 访问控制 → 访问授权 |
| 权限核对 | 某用户最终可用的账号、授权来源和缺失权限 | 访问控制 → 权限核对 |

## 日常配置

1. 创建用户、组织用户组；给用户或组分配操作角色。
2. 添加设备，配置连接地址、主机指纹及默认登录凭据。已有设备的配置窗口分为「接入方式」和「默认登录账号」。
3. 需要其他 Linux 身份时，在「登录账号」中新增直接 SSH 或 Agent sudo 切换账号。此处只管理账号与凭据。
4. 在「访问授权」点击新增，选择一种授权对象类型（用户组、用户或角色），再选择对象、设备和可用登录账号。组成员和继承角色实时参与匹配。
5. 用「权限核对」查看生效来源。获得账号授权仍须具备角色中的终端连接权限；sudo 切换和特权登录另须「使用 sudo／特权账号」。管理员保留全平台访问权限。

新访问授权同时提供设备范围与所选账号的使用权，不会授予该设备的其他登录账号。角色只决定操作权限，不自动提供任何设备或账号的使用权；设备组仅为分类标签，调整标签不会改变授权。多个授权来源取并集，删除一条规则后，其他匹配规则仍可能允许访问。

网页和平台 SSH 入口使用同一份账号列表与授权检查。只有一个可用账号时可以直接连接，没有可用账号时拒绝连接。旧客户端不传 `account_id` 时仍选择默认账号，但同样检查默认账号授权，不能绕过已撤销的规则。每次创建、附着、输入、输出和定时检查都会复查权限；删除授权时立即检查已有会话及待使用的连接票据。

## 默认登录账号

每台设备有一个稳定标识的默认登录账号，身份及凭据继续引用原设备接入配置，不复制或重加密私钥、口令和 sudo 密码，也不会更换设备身份或 SSH 主机密钥。Agent 通道使用进程运行账号；SSH 通道使用原接入账号。Agent 及备用 SSH 的优先级保持原状。

默认账号在账号列表和访问授权里与其他账号一同展示。它不能作为普通账号删除；可以删除其「继承原设备授权」规则、增加精确的用户／用户组／角色授权。已有凭据仍可从「配置默认账号」维护。

原默认账号对既有用户的权限原样保留，包括既有 SSH 账号的 Linux 权限。新规则单独授权默认 root SSH 账号、且没有匹配旧兼容规则时，还须具备 sudo／特权账号权限。

## 既有配置的兼容

升级采用事务迁移：

- 每台既有设备生成一条可见的默认账号规则「继承原设备授权」。它只引用原用户／用户组的设备范围，包含原来的全部设备和未来设备语义。
- 既有目标账号的用户、用户组和角色授权转换为带来源标记的规则，继续与原设备范围取交集，不将原先无权访问设备的人变成有权访问。
- 新规则提供的设备范围不会激活「继承原设备授权」规则，防止授权一个附加账号时意外获得默认账号。
- 原用户／组设备范围保留在用户／组编辑表单的「原设备授权」折叠区，仍可维护；新增授权使用统一入口。
- 已删除的兼容规则在重启后不会自动恢复。数据库迁移可重复执行，不产生重复授权；删除用户组、角色或登录账号会级联清除对应授权。
- 旧 `/devices/:id/accounts` 接口继续兼容 `allowed_users`、`allowed_groups`、`allowed_roles`。凭据编辑省略这些字段时保留授权规则及其语义。旧客户端提交未变化的授权字段时也保留原规则；新增授权对象按旧设备范围规则处理。

新接口：`GET /api/v1/devices/:id/login-accounts` 返回当前用户可用的统一账号列表；管理员通过 `GET/POST /api/v1/access-authorizations` 管理授权，通过 `DELETE /api/v1/access-authorizations/:id` 加版本号撤销规则，通过 `GET /api/v1/access-authorizations/effective/:userId` 核对生效结果。授权管理与权限核对接口仅允许管理员；任何接口都不返回凭据明文。

## 验证

服务端测试覆盖默认账号隐式／显式选择、迁移保密与范围保持、规则删除后会话及票据失效、重启不恢复已删规则，以及只授权附加账号时不能访问默认账号。前端测试覆盖凭据编辑不提交授权、授权对象选择和生效来源展示。

`FLEET_TEST_BROWSER_CHANNEL=msedge npm run test:target-accounts` 在隔离 Linux 容器和浏览器中验证真实 sudo、网页与 SSH 统一规则、无旧设备范围的精确授权、默认账号的撤销和完整界面流程；不修改已有部署。这些本地结果不等同于 CI 或生产验收。

## 保留的人员、审计与 API 细则

以下能力与既有数据保持兼容。原用户／用户组设备范围在兼容折叠区维护；新增资源授权使用前文统一入口。角色权限仍取并集并适用于合并后的设备范围，不支持同一用户在不同设备分别绑定不同操作角色。命令任务仍以 Agent 原运行账号执行，不随终端所选登录账号切换身份。

## 会话可见范围

`recordings.read` 仅允许查看本人在授权设备上的会话、回放和导出。普通用户和未授予跨用户查看权限的自定义角色不能查看其他人的会话；设备范围为“全部设备”也不扩大到他人的会话。管理员以及显式授予 `recordings.read_all`（查看他人会话与录制）的自定义角色可审计授权设备上的其他会话。后者依赖 `recordings.read`，可在“访问控制 → 角色”配置，也可通过用户组继承。

列表在分页和搜索之前按所有者过滤，回放和导出逐次校验同一权限；获知会话 ID 不能绕过授权。审计权限不允许接管或结束其他人的终端；结束会话仍仅限本人或管理员。迁移 `022_recording_visibility.sql` 为管理员和审计员保留跨用户审计能力，不自动授予运维、业务或已有自定义角色，也不修改历史录制。

## 任务与操作审计可见范围

普通用户仅能查看本人在授权设备上的任务、详情和输出，以及本人发起的操作审计。跨用户查看分别需要 `tasks.read_all`（查看他人任务）、`audit.read_all`（查看他人操作审计），在角色表单中配置，并依赖对应的基础查看权限。管理员拥有这些审计权限；普通用户和未勾选对应权限的自定义角色不自动获得。升级保留的旧审计角色仍保持原权限。审计员仍受设备范围限制；审计权限配合“全部设备”范围才可查看其他人的平台级事件，例如登录及系统设置。本人操作审计保留，即使之后失去相关设备权限。

所有者限制在分页、筛选之前生效，详情和输出下载也校验。取消任务仅限有执行权限的本人或管理员，查看他人任务不授予取消权限。迁移 `023_history_visibility.sql` 不修改任务或历史审计。

## 账号与会话

开启首次改密后，初始密码只允许查看本人登录状态、修改密码和退出登录；设备、任务、审计、录制与平台 SSH 入口在改密前均被服务端拒绝。刷新或重新登录也无法跳过。用户需先在网页完成改密，再使用新密码登录；账号列表显示「待首次改密」，完成后自动清除。新密码仍须至少 8 个字符且同时包含字母和数字，不能与初始密码相同。管理员重置待改密账号的密码不会清除该要求。现有账号和初始管理员不受影响，旧 API 请求省略 `must_change_password` 时沿用原行为（false）；网页创建表单默认传 true。关闭网页管理的部署应在关闭前完成首次改密，或创建账号时取消此选项。

所有已登录用户（包括尚未分配角色的账号）都可在左下角账号区点击「修改密码」，填写当前密码、新密码和确认新密码。新密码要求 8–1024 字符，同时包含英文字母和数字且不能与当前密码相同。管理员仍可在「访问控制」重置其他账号密码。

个人修改只操作当前认证账号，不接受目标用户 ID。当前密码错误不会退出登录，每账号每分钟最多尝试 5 次。成功后撤销该账号所有网页登录和 SSH 登录令牌，关闭其活跃终端，回到登录页使用新密码登录；其他用户不受影响，已有历史录制保留。密码、会话撤销及审计在同一事务中写入，失败不会留下部分更新。审计区分本人修改与管理员重置，不记录明文或哈希。


- 创建账号、重置密码要求 8–1024 字符，同时包含英文字母和数字；密码仅保存为加盐哈希，不返回密码或哈希，也不记入操作审计。
- 停用账号、重置密码、修改用户、角色或用户组授权会撤销受影响用户的登录令牌，并立即关闭其活跃网页和 SSH 终端。重新登录后使用新权限。调整设备标签不会触发这种失效。
- 权限变更不会回滚已在 Linux 上执行的操作，也不会自动取消之前创建的命令任务；需在任务中心另行取消并核对结果。
- 不能移除最后一个启用的管理员，也不能停用当前管理员或撤销自己的管理员角色，包括通过用户组变更。
- 表单以 `revision` 防止覆盖他人修改，冲突后需刷新列表再编辑。用户与用户组双向成员编辑会更新关联版本；设备标签成员变动也更新该标签的版本。

## API 和数据

管理端点均仅允许管理员访问，写操作事务性保存并记录 `access.*` 审计：

| 接口                                                                 | 作用                                                                     |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `GET /api/v1/access`                                                 | 权限目录、用户、角色、用户组、设备组                                     |
| `POST /api/v1/users`、`PUT /api/v1/users/:id`                        | 创建、修改或停用账号                                                     |
| `POST /api/v1/users/:id/password`                                    | 重置密码                                                                 |
| `POST /api/v1/roles`、`PUT/DELETE /api/v1/roles/:id`                 | 自定义角色                                                               |
| `POST /api/v1/groups`、`PUT/DELETE /api/v1/groups/:id`               | 用户组                                                                   |
| `GET /api/v1/device-groups`                                          | 管理员读取设备组列表                                                     |
| `POST /api/v1/device-groups/batch`                                   | 批量添加或移除标签（`operation: add/remove`，`device_ids`，`group_ids`） |
| `POST /api/v1/device-groups`、`PUT/DELETE /api/v1/device-groups/:id` | 设备分类标签                                                             |

用户和用户组的 `device_scope` 是具体设备 ID 数组或 `"*"`。用户的 `group_ids` 是所属用户组，用户组的 `member_ids` 是成员。设备组通过 `device_ids` 保存可为空的成员列表；设备与设备组为多对多关系。`GET /me` 和登录返回生效权限与合并后的设备范围；`GET /devices` 附带 `device_groups` 标签数组，可为空。

迁移 `014_access_control.sql` 保留原用户角色和设备范围；`015_device_groups.sql` 增加可选设备标签，不为设备自动创建成员关系。服务重启不会重新补回已撤销的角色。环境变量中的管理员账号仅用于空数据库的首次初始化，改名或停用后不会被旧启动配置重新创建。当前管理上限为 1000 个用户、100 个角色（含内置）、100 个用户组、100 个设备组。单次设备组编辑、批量操作最多选择 1000 台设备，每个设备组最多包含 1000 台设备。

## 验证

后端测试覆盖旧数据迁移、设备未分组/多标签、标签与权限独立、跨角色/设备拒绝、用户组继承、密码重置、停用、管理员防锁定、并发版本、敏感信息不回传，以及网页/SSH 活跃终端的权限撤销。前端测试覆盖表单、设备标签批量选择、授权依赖和过期编辑。协议夹具覆盖全部新增接口及非法字段、重复设备和敏感字段拒绝。

`npm run test:access:browser` 启动隔离测试平台和前端，用真实浏览器完成角色、分组、用户创建与授权变更，验证设备组管理入口、按组筛选、跨筛选多选、批量增删标签、可见设备、标签不影响连接、授权撤销和移动端表单。终端后端使用协议测试替身，真实 Linux PTY 另由 `npm run test:terminal:browser` 验证。这些是本地验证，不代表 CI 或生产安全验收。

`npm run test:password:browser` 在隔离数据库中验证普通用户修改密码、旧密码失效、新密码用于网页及 SSH 登录、本人活跃网页和 SSH 终端撤销且已录制输出保留、其他账号不受影响，以及无角色账号的入口和移动端对话框。需要已信任的 `.dev/tls` 证书和已构建的前后端；可用 `FLEET_TEST_TLS_DIR`、`FLEET_TEST_BROWSER_CHANNEL=msedge` 指定测试证书及浏览器。该测试的 Agent 为协议替身，不代表真实 Linux PTY 验收，也不会修改现有环境账号密码。

`npm run test:sessions:browser` 在隔离数据库和浏览器中验证同设备不同用户的网页/SSH 历史会话隔离、直接请求他人录制/导出被拒绝、本人回放与导出、审计员设备范围和管理员查看。使用预置录制数据，不连接实际 Agent 或 SSH 主机。
