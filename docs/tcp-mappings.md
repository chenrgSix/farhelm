# 网页端口映射

管理员在「设备 → 接入配置 → 端口映射」新增、编辑、启停和删除 TCP 映射。数据库客户端直接连接平台的映射端口，不需要运行 OpenSSH 或输入平台密码。此功能与原有 `-J` / `-L` 并存，映射配置只由管理网页及其管理员会话 API 管理，不提供 SSH 配置命令或 API Token 管理权限。

例如，平台在 `192.168.1.5:11433` 监听，经选定设备连接 `192.168.0.4:1433`。客户端使用 `192.168.1.5:11433` 和数据库账号密码；`2222` 仍是 SSH 入口，与映射端口不同。

## 配置

1. 在设备的「TCP 转发」中开启「允许 TCP 转发」。
2. 在「端口映射」中新增映射，填写名称、平台监听 IP / 端口、目标 IP / 域名及端口。
3. 填写允许连接的来源 IP 或 CIDR，每行一项，支持 IPv4、IPv6，最多 64 项。空白、域名或 `*` 不被接受。
4. 勾选「启用映射」并保存。确认列表显示「正在监听」后，让客户端连接平台实际 IP 和配置端口。

新映射默认停用，监听地址默认 `127.0.0.1`，仅平台本机可访问。对其他电脑开放时填写平台实际可绑定的内网 IP；`0.0.0.0` 表示全部 IPv4 网卡，`::` 表示全部 IPv6 网卡（不同时接收 IPv4）。监听端口范围为 1024–65535，目标端口为 1–65535。目标域名在出口设备侧解析。

项目的 Linux Compose 使用宿主机网络。平台监听 IP 可以直接填堡垒机的实际内网 IP，例如 `192.168.1.5`。新增映射只需在网页上选一个空闲端口，主机防火墙须允许对应来源访问。目标地址从选中的设备访问，例如 `192.168.1.5:10001 → A 的 127.0.0.1:8000`。如果使用自定义桥接网络或 v0.2.18 的 Compose，监听 IP 需属于容器，并由部署者另外发布对应端口。

端口已被其他程序或映射占用时，保存失败，原配置与连接保持不变。修改同一端口的监听地址可能与旧监听冲突，此时先停用映射再修改。绑定失败的原因显示在网页，修复后编辑并保存可重试。重新加载映射会读取最新运行状态并丢弃未保存的编辑。

## 访问边界与生命周期

- 来源白名单按平台 TCP socket 实际看到的客户端地址检查，不信任 HTTP Header 或 PROXY protocol；经过 NAT 时看到的可能是共享出口地址。IPv4 白名单也识别 IPv4-mapped IPv6 表示。
- 映射入口不识别平台用户；白名单内的客户端均可尝试连接目标服务。因此数据库等目标服务须保留自己的认证。平台入口到客户端是原始 TCP，远程传输加密由目标协议的 TLS 提供。
- 配置归创建管理员所有，修改配置不会转移归属。创建账号被停用、失去管理员权限或要求修改密码，设备被撤销、关闭转发或失去连接权限时，监听及现有连接停止。平台持久记录暂停原因。恢复权限或重启平台后仍须在网页重新保存启用的映射。退出网页不会关闭持久映射。
- Agent、纯 SSH 及备用 SSH 共用出口选择和权限检查；Agent 需要支持 `tcp.forward.v1`（0.2.16+），SSH 目标沿用已保存的凭据、主机指纹、网络路由及默认账号/sudo 授权，并须允许 TCP 转发。
- 修改、停用、删除映射会断开其现有及正在建立的连接。其他映射、普通终端不受影响。设备或出口暂时离线时，新连接失败；既有连接不自动切换出口，新连接会重新选择可用出口。
- 配置持久保存，平台启动后恢复已启用映射。端口冲突、不可用绑定地址或权限问题不会阻止平台本身启动，失败项显示「未监听」。
- 每设备最多 16 条映射，全平台最多 128 条；每映射最多 16 个连接，并与 SSH 转发共用每设备 32、全平台 128 个通道额度及每连接一小时限制。支持二进制、背压和 TCP 半关闭。
- 配置变更记录实际操作管理员；连接记录标为「客户端身份未认证」，另列来源 IP 和映射创建人。按操作人筛选不会把映射流量计入创建人的操作。另记录映射 ID、出口设备、目的地址、字节数及关闭原因，不保存转发内容。被拒绝连接的审计每条映射最多每秒一条，避免扫描耗尽存储；审计不可写时不建立转发。
- 网页「审计」区分来源白名单拒绝、账号权限不足、设备关闭转发、并发超限，以及设备连接目标时报告的拒绝或超时。每条映射第 17 个 TCP 连接也记录 `FORWARD_LIMIT`。设备关闭转发会停止监听；停止后到达未监听端口的请求不会产生客户端审计。此时可查「修改设备 TCP 转发权限」事件或映射的暂停原因。

## 管理接口

仅管理员网页登录会话可调用；API Token 不具备管理员身份。接口均位于 `/api/v1/devices/:id/tcp-mappings`：

- `GET`：读取映射列表及 `status`、`error`、`connections` 运行状态。
- `POST`：新建，提交 `v: 1`、`name`、`enabled`、`listen_host`、`listen_port`、`target_host`、`target_port`、`source_cidrs`。
- `PUT /:mappingId`：提交相同字段及当前 `revision`，修改或重试监听。
- `DELETE /:mappingId`：提交 `{ "v": 1, "revision": 当前版本 }`。

版本过期返回 409，需重新读取；配置写入和审计在同一事务内提交，失败不改变原配置。`status=listening` 只说明监听已绑定，不表示目标数据库已通过认证或可达。
