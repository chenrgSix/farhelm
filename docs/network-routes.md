# 内网 / VPN 优先与公网备用

在「设备总览」的「网络通道」列点击「网络策略」。管理员可配置，其他有设备查看权限的用户只能查看所属设备的状态。此设置与 Agent / SSH 接入方式独立；原设备 ID、分组、权限与历史录制保持不变。现有设备默认沿用原配置，不自动迁移网络。

## 配置

- **VPN 优先、公网备用**：内网入口优先，配置了备用入口才允许回退。不填备用入口时只尝试内网。
- **仅内网 / VPN**：禁止尝试公网备用业务入口。内网不可达则连接失败；Agent 重启后也遵守已持久保存的策略。
- Agent 填写平台内网 HTTPS 地址和可选的公网备用地址；SSH 填写目标内网 IP / 端口和可选的公网地址 / 端口。SSH 两条路径共用已保存的账号、密钥与主机指纹，必须对应同一台设备。
- 内网连接必须固定到私有 IP（RFC1918、CGNAT、IPv6 ULA，或用于本地验证的回环地址）。Agent HTTPS 地址可以使用证书域名，同时填写“内网/VPN 连接 IP”；HTTP 与 WebSocket 都连接指定 IP，仍校验证书域名，不通过 DNS 转向公网。SSH 内网地址直接填写 IP。IPv6 HTTPS URL 使用方括号。HTTP 代理环境变量不会接管 Agent 的平台请求。
- Agent 验证 TLS 证书与原平台身份；证书须匹配 HTTPS 地址中的域名或 IP，所用 CA 须事先受信。指定连接 IP 时可复用平台已有的域名证书，无需为 VPN IP 另签证书。现有私有 CA 签发与同步功能仍适用。平台地址同步不会覆盖已启用的逐设备网络策略。
- 修改配置要求设备没有活跃终端和已下发/正在执行的任务。配置 revision 防止覆盖他人修改。SSH 下次连接生效；Agent 需要 0.2.5 或更新版本，未确认策略前暂停该设备的 Agent 任务下发及新 Agent 终端。离线 Agent 重连后接收策略；旧 Agent 显示需升级。配置停用后恢复原地址。

## 连接行为

Agent 将配置保存在原状态目录，连接前验证候选平台的 TLS、设备认证及平台实例身份。内网连接失败时，VPN 优先模式尝试配置的备用入口。已连接的 Agent 每 30 秒检查路径；在公网通道上连续三轮确认内网恢复后，等待任务、上传、下载及终端空闲再重连内网，不迁移已有 Shell 或重放输入。实际链路中断可能结束原会话，重新连接会创建新的录制会话。

SSH 每次新建连接均优先尝试内网，只在网络连接失败或超时时尝试备用。主机指纹不符、账号认证失败、PTY 打开失败不会回退；终端打开后也不会自动切换到另一台 Shell。网页终端和平台 SSH 入口共用相同选路、设备范围、账号权限、撤销检查与先录制后转发流程。

## EasyTier 的实际路径

平台不安装、启动、停止或改写 EasyTier。请先独立组网：Agent 到平台的状态由 Agent 采集；SSH 到设备的状态由平台主机采集。采集使用本机 `easytier-cli --rpc-portal 127.0.0.1:15888 --output json route` 和系统出口路由，并核对出口网卡确实持有该 EasyTier 实例的虚拟地址。Linux 需要 `ip`（iproute2）；平台在 macOS 上读取 `route` 和网卡信息。仅执行固定只读命令，有超时和输出大小限制，不运行前端传入的 Shell。

- **P2P 直连 / 中继**：目标虚拟 IP 精确匹配且实际出口网卡吻合；不会仅凭安装了 EasyTier、网卡名称、私有 IP 或 ping 成功下结论。
- **未检测到 EasyTier 路径 / 路径未知**：CLI 不可用、RPC 不可达、多实例/子网代理或路由信息不足时如实显示；直连优先与延迟优先路径冲突时也保留未知。
- Agent 状态属于当前认证连接，断连后显示历史参考；SSH 显示最近建立连接时的观测，不把历史成功当实时在线。内网可用不等于业务健康，EasyTier 中继也不等于公网业务入口回退。

仅内网模式限制 Farhelm 的业务目标地址，不禁止 EasyTier 底层利用互联网、共享节点或中继。需要完全隔绝公网时，必须具备实际内网/专网链路，并在 EasyTier 和网络边界实施相应策略。公网备用路径如果依赖同一 VPN 的默认路由，也不能被视为独立灾备链路。

## 验证

服务端回归覆盖策略校验、设备范围、管理员写权限、版本与认证连接绑定、SSH 内网优先/备用、禁止回退、身份拒绝、网页/SSH 入口及录制。Rust 测试覆盖持久化更新和重启、固定私网地址、EasyTier 路径证据。前端测试覆盖模式切换、清除公网字段、只读用户和旧 Agent 提示。

`node tests/e2e/network-routes.mjs` 使用三个一次性 Linux 容器及独立 Docker 网络验证真实 EasyTier P2P / 中继、Agent 回退、持续终端的恢复等待、仅内网重启与 SSH 两种入口。需准备 Linux Agent、测试镜像与浏览器；不接触已有部署。在 ARM64 开发机上可执行 `bash tests/e2e/network-routes/build-image.sh` 构建测试镜像（需先有 `farhelm-agent-dev:local`）。通过 `FLEET_ROUTE_AGENT_BIN` 指定 Linux Agent 二进制；默认读取 `.dev/route-target/debug/farhelm-agent`。结果位于 `.test-output/network-routes-e2e.json`。真实跨地域 NAT、运营商限流及公网计费不由本地容器验收替代。
