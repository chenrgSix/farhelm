# Farhelm 架构审查与分阶段验收

日期：2026-10-14。状态：实现前设计审查。实际实现与测试状态以 README 和 test-report.md 为准。

后续用户已选择自行配置单 Linux 账号，ADR-006 的双 UID 设计提议不再生效；当前决定见 adr/0006.md。

已读交接包全部 6 个文件。决策优先级：`DOT_HANDOFF.md` > 历史设计、协议示例、SQL。本文保留 Rust/Tokio Agent、TypeScript/Fastify 单体、Vue 3、SQLite WAL、文件目录和 TLS 反代；不增加 MQ、Redis、Kubernetes，也不实现 EasyTier 生命周期管理、主机旁路审计或 SSH 依赖。

## 结论

架构适合先完成单机纵向链路。主要风险不在语言选型，而在崩溃语义、持久化确认、完整审计与资源上限，以及 Agent 自身和执行命令的权限隔离。先固化下面六项 ADR，再实现 P0/P1，可以避免 P2 重写可靠性和审计层。

历史稿需要明确淘汰：`HOST_TLOG` 审计类型、旁路 SSH 必须纳管的约束、旧 P0–P8 排期、EasyTierManager 以及允许静默丢弃审计输出的解释。最新稿中的第一条综合验收跨越 P0–P3，不能把终端录像和私网切换误报为 P1 已完成。

## ADR-001：单体边界与一条执行链

**决定：** 保持现有技术栈和单实例。REST `commands` 是用户入口，Agent 仅有一条持久化任务执行管线；`AGENT_EXEC` 是任务的一种，不另建绕过 journal/outbox 的 `exec.request` 快捷通道。

- `task_id` 标识一次设备执行；`job_id` 标识业务/批量请求；`execution_id` 如保留，只是审计关联，不触发第二次执行
- Agent 只主动连接；公网 WSS 始终负责控制，独立 HTTPS/流连接负责大输出、文件和 PTY。P1 就提供最小输出上传接口，私网选择策略到 P3 再实现
- 未配置 EasyTier 时 Agent 正常工作；控制在线、私网数据可达、业务健康分别建模，未采集的状态为未知，不能默认健康
- 队列由持久化任务表和单进程 scheduler 实现；内存连接表仅作连接索引，不是真实任务状态
- API 身份、Agent 身份和数据上传授权分离。设备名称、部门、用户 ID、角色不能由 Agent 上报即成为可信授权依据

**代价：** 单机仍是故障点，SQLite 不承诺 500 台持续终端满负荷性能。以 P5 实测决定是否迁移 PostgreSQL，而非预先堆基础设施。

## ADR-002：设备密钥、注册与认证

**决定：** 每设备 Ed25519 密钥、经管理员授权的一次性短 TTL 注册令牌、TLS 校验、短期设备访问令牌。签名原语使用成熟库及 [RFC 8032 测试向量](https://www.rfc-editor.org/rfc/rfc8032#section-7.1)，不自行实现密码算法。以下挑战协议是本项目设计，需要契约与攻击测试。

1. 注册令牌随机高熵，服务端仅保存摘要；绑定用途、归属和最大使用次数，P0 默认一次。核销、设备创建和审计同一事务完成，阻止并发双重兑换
2. 注册请求除 token、公钥外，必须证明持有对应私钥。签名内容使用明确的字节编码与域分隔，绑定服务实例、用途、challenge ID、随机 nonce、公钥、注册 token 摘要、到期时间；不要直接签不稳定序列化的 JSON
3. 后续认证挑战绑定 device ID、公钥版本、服务实例、用途及过期时间；至少 256-bit 随机 nonce；服务端验证后原子标记已使用，再发短期、限定 audience/scope 的 token。挑战及失败尝试限速
4. 注册响应丢失时，用原密钥证明持有权找回同一个设备身份；不得再次创建设备，也不能仅凭曾用 token 获取新凭据
5. Agent 通过 Authorization 传 token，禁止放 URL、常规日志、浏览器页面。已撤销设备关闭旧连接并拒绝新认证，长连接在授权到期时重新认证或重连
6. P0 即具备真实管理员身份与设备范围检查。开发可用显式初始化的本地管理员，不接受客户端自报 `actor_id`、默认公共密码或无需登录的执行接口。企业 SSO/MFA 接入后续确定

**故障原则：** 本地私钥/journal 丢失不能悄悄当“新安装”继续旧任务；进入需要重新授权注册的恢复流程。服务端 TLS 失败不得降级跳过校验。

## ADR-003：至少一次投递，疑似已执行绝不盲目重跑

**决定：** 任务不可变，Agent 本地持久化去重；运行状态不确定即 `UNKNOWN`。这不是通用 Shell exactly-once 保证。

执行顺序：

1. 服务端授权后，在一个事务内记录不可变请求、操作人、授权决策、任务及创建审计，然后才能发送
2. Agent 校验 task ID、设备、TTL、参数与本机策略；原子写入 `ACCEPTED` 和 accepted outbox 事件，持久化完成后再回应
3. 调度器在执行前检查 TTL、并发和取消状态；持久化 `RUNNING`/started 事件后才启动进程。此处与 OS spawn 不可能组成数据库原子事务
4. 完成后先封存输出，再原子提交结果与 finished outbox；断线只影响发送，不改变正在执行的命令
5. 重启发现 `ACCEPTED` 可按未开始任务恢复；发现 `RUNNING` 且没有可靠完成记录则先清理/核对残留进程，再标 `UNKNOWN`，不自动重启该命令。即使崩溃发生于写 RUNNING 后、spawn 前，也保守按 UNKNOWN

补充约束：

- 相同 task ID、相同不可变 payload 仅返回已有状态；相同 ID 不同 payload 拒绝并审计。使用请求哈希和唯一约束，不仅靠内存锁
- P1 每设备任务并发固定为 1，Agent 单实例锁防止两个进程同时使用同一个身份/journal；并发槽在进程清理和结果封存完成后释放
- Web 重复点击/HTTP 重试使用绑定操作人与请求内容的 idempotency key；仅在 Agent 去重仍会漏掉两个不同任务 ID 的重复操作
- `SENT` 仅表示尝试发送，丢失 accepted ACK 时只能重发同一个 ID；新连接取得唯一发送权，旧连接不能继续下发新任务
- 单纯失联显示连接丢失/等待补传，不立即把任务定为 UNKNOWN。UNKNOWN 是有执行歧义的事实；以后收到原始可信完成证据可以附加核对记录并修正展示，历史不可覆盖
- `EXPIRED` 仅指尚未开始已过 TTL；`TIMED_OUT`/`CANCELLED` 需有实际终止和清理证据，取消请求本身不是终态。无法确认终止则保留不确定性
- P1 禁止自动重试 UNKNOWN。用户确认后另建带 `retry_of` 的新任务并提示原操作可能已生效；“幂等模板自动重试”以后逐模板审核
- 去重墓碑不能随已 ACK outbox 一起删，也不能任意按短期 TTL 清理；保留范围必须覆盖服务端所有合法重投/恢复路径

## ADR-004：ACK、事件顺序和文件提交必须可恢复

**决定：** ACK 代表约定数据已经持久化，不代表收到了网络帧。事件是不可变事实，任务状态是受状态机约束的投影。

- 事件带稳定 `event_id`、`task_id`、持久化递增 `seq`、类型、payload hash；身份取已认证连接。约束 `(device_id,event_id)` 与 `(task_id,seq)` 唯一，同 ID 异内容拒绝
- accepted、started、finished 都进入 outbox；序号分配、状态写入和 outbox 插入处于同一事务，重发使用原 ID、原序号、原内容。服务端按序应用，缺口请求补传；迟到 started 不允许把已完成任务改回 RUNNING
- 服务端事务同时提交事件、可应用的状态变更与审计后才能发 `event.ack`。如先接到乱序事件，可持久化为待应用事实并逐事件 ACK，但不可越过缺口宣称审计完整
- ACK 丢失只造成安全重传；Agent 仅删除匹配自己设备/事件的 outbox 条目，删除也应可重入。不要发送跨缺口的“累计确认”
- P1 最终结果先上传输出对象。服务端执行临时文件写入、大小/hash 校验、文件同步、同文件系统原子 rename、必要的目录同步，之后提交对象索引。只有必需输出可读且持久化，才完成最终审计并 ACK finished
- 文件与 SQLite 不共享事务：优先让崩溃产生可清理孤儿文件，而非指向不存在文件的已确认记录；启动时对账，GC 只清理确认无引用且超过安全期的对象
- Agent 也必须先可靠封存输出，再写引用它的 finished outbox；对象在服务端确认前不得删除。`ACK_RECEIVED` 与本地删除之间崩溃不影响重放
- 两端任务/审计数据库明确设置 WAL、foreign keys、busy timeout 与 `synchronous=FULL`。WAL 单独不等于断电持久化，NORMAL 的已提交事务在掉电/系统崩溃后可能回滚；见 [SQLite 官方 synchronous 说明](https://www.sqlite.org/pragma.html#pragma_synchronous)。实际持久性仍依赖文件系统与存储兑现同步语义
- 不在数据库事务中等待网络/大文件写入；限制单次批量事件大小。备份使用 SQLite 支持的在线/一致性方式，并包含被索引的输出文件，必须实做恢复验收

## ADR-005：完整审计与有限资源并存，不能靠静默截断

**决定：** 区分 UI 预览限额、单对象/任务硬限额、总磁盘水位和公网传输配额。完整指在明确边界内成功录下的真实证据，不承诺无限输出。

- UI 仅显示前若干字节可以截断，原始 stdout/stderr 仍完整存储；分别记录总字节、预览截断、审计完整性。不要复用一个 `output_truncated` 布尔值混淆两者
- 原始输出按字节流落盘，stdout/stderr 并发持续排空；展示时处理 UTF-8 跨块/非文本输出，不用无限 `read_to_end` 聚合到内存
- 高水位先拒绝新任务，运行中在安全余量内触发停止/终止，预留关键回执与管道尾部空间。不能继续执行并丢弃超限字节，再把结果写成“成功且完整”
- 发生硬限额/写盘失败，记录 `OUTPUT_LIMIT` 或 `AUDIT_STORAGE_FAILURE` 原因；保存已捕获前缀、最后可靠偏移、退出信号和清理结果。若确有字节丢失，明确 `audit_complete=false`，正常退出码也不能掩盖审计失败
- 公网配额不足时，结果元数据和“输出待同步”可以上报，原始输出保留本地；不能假称中央审计完整，也不能为继续任务清理未确认的 outbox/输出
- P2 PTY 统一给输出、resize、起止事件编号并记录单调相对时间。中央先可靠记录连续事件，再向浏览器放行；内存队列不能算持久化。短批同步可减少开销，但只能转发已持久化的批次
- 录像未就绪不能开放会话/输入。录制通道失效时停止输入并冻结/关闭会话；缓冲有界，缺帧标记不可补成“完整”。无法无损续流时结束原 session，明确中断再新开
- 不记录隐藏键击；输出本身仍可能含秘密。审计查看、回放、导出均需授权并留下审计记录；HTML/ANSI/终端控制序列不能被当成可信网页内容
- SHA-256/哈希链可发现不一致，但拥有同机数据库及文件写权限的管理员可同时改内容和摘要；不能宣称天然不可篡改。更强独立见证/签名与外部只追加存储属于后续安全范围

## ADR-006：低权限执行、密钥隔离与完整进程生命周期

**历史提议，已被用户单账号决定替代；见 adr/0006.md：** Agent 控制身份与 Exec/PTY 执行身份分离；执行目标是固定低权限账号，不是客户端任意 UID。全部经平台的操作仍按真实平台用户归属，不需要每员工 Linux 账号。

- 建议固定 `farhelm-agent` 保存设备密钥、journal/outbox；固定 `farhelm-exec` 执行命令。仅 chmod 0600 无法防止同 UID 的任意命令读取密钥和改 journal，所以不能用同 UID 冒充身份隔离
- 通过范围极小、受审查的执行启动器/系统服务边界切换到固定执行 UID，并建立任务资源边界。它不接受 root shell、任意 UID、任意服务名或调用者指定的提权规则。代码可先实现接口与测试，真实安装及授权单独确认
- 业务模板为版本化 action + schema + 固定程序/参数映射；不拼接 `sh -c`。运维显式 Shell 请求如允许，应记录 shell 程序和完整脚本文本/hash，不能与业务模板混用
- 清理继承环境、关闭无关 fd、固定 PATH/工作目录策略；私钥、数据库和控制 socket 对执行账号不可读写。`journalctl` 无权限时明确返回权限失败，不能自动加组或 sudo
- 每次任务建立独立进程组：取消/超时先 TERM，宽限后 KILL，wait/reap，并持续处理输出。Tokio 丢弃 Child 默认不会停止子进程，单杀主 PID 也不是子树清理；见 [Tokio Child 文档](https://docs.rs/tokio/latest/tokio/process/struct.Child.html)
- `setsid`/double-fork 可脱离普通进程组；需要强子树清理时使用每任务受控 cgroup/系统服务单元，且执行账号不能把进程移出去。cgroup v2 的 kill 接口覆盖子 cgroup，参见 [Linux cgroup v2 文档](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html)。目标内核和权限须探测；不满足时禁止承诺“任意命令后代全部清理”
- Agent 意外退出/重启必须检查残留任务边界；不能只保存 PID 后盲杀，防止 PID 复用。服务级清理与任务级清理都需测试
- 同一 `farhelm-exec` 下多个 PTY 可以分别录制、归属平台用户，但共享该账号的文件/进程权限，不构成互相强隔离。若业务要求不互信会话隔离，另议每会话身份/沙箱，不默默扩大本期范围

## P0–P5 里程碑与验收门槛

### P0：可认证、可观察的通信骨架

交付：可构建的 Rust Agent、Fastify/Vue 项目；版本化 schema；管理员登录；一次性注册、Ed25519 挑战、公网 TLS/WSS、心跳/重连、设备页；本地启动说明。

验收：
- 授权的测试 Linux 未安装/未启用 SSH、未安装 EasyTier，仍能注册并上报心跳；未检测状态显示未知
- 注册 token 到期、重复兑换、并发兑换、错误签名、挑战重放、替换 device ID、撤销后的新旧连接全部拒绝
- 注册回包丢失和 Agent 重启后仍恢复同一设备身份；服务重启后设备记录不丢
- 错误 TLS、过大帧、未知协议版本、无认证/跨角色管理请求受控拒绝，无敏感 token 日志
- 断网重连使用抖动退避；同一设备旧连接不再拥有发送权；UI 三类健康状态不混用
- lint/typecheck、Rust check/test、协议正反例、基础集成测试通过。只跑本地 CA 不等于已通过真实公网 TLS/NAT 验收

### P1：单条授权 Exec 的可靠闭环

交付：管理员从 Web 对授权设备执行单条命令；任务、结果、stdout/stderr、身份和授权审计；本地 outbox、HTTPS 输出对象、结果补传；TTL/取消/超时/输出与并发限制。

验收：
- `uptime`、有权限的有限日志读取及非零退出命令显示原始 argv、cwd、stdout/stderr、退出码、平台用户、设备与 task ID
- HTTP 请求重试、同 task ID 重发三次、丢 accepted/finished ACK 均不新增一次执行；同 ID 不同 payload 拒绝
- 在 accepted 提交前后、RUNNING 提交前后、spawn 后、输出封存后、finished 事务前后、服务端 commit/ACK 间逐点注入崩溃，验证预期恢复或 UNKNOWN，不盲目重跑
- 任务运行时断控制连接，进程按规则继续、结果重连补传；事件重复/乱序不能导致状态回退或审计伪完整
- 过期未执行任务不上线补跑；取消请求与真实结束区分。超时命令含 fork/setsid 后代，按声明的进程隔离能力验证清理；不能确认时不得伪报已取消
- stdout/stderr 同时大量输出、非法 UTF-8、管道尾部、低磁盘/写失败、超配额有有界内存和明确审计失败；无静默丢弃；服务重启仍能读全部已确认对象
- 执行账号无法读取 Agent 私钥、改 journal/outbox 或变更执行 UID；业务/审计员/跨设备用户不能调用任意 Exec
- 恢复备份并核对任务、审计和输出索引；全量 lint/typecheck/unit/integration/e2e 记录通过、失败及未运行项

### P2：Agent PTY 与强制时序录像

交付：xterm.js、中央会话网关、Agent 主动流、授权回放和查看/导出审计；SSH Proxy 暂不做。

验收：两个平台用户在同一设备开独立 session，`top`、`vim`、Ctrl-C、resize 和 UTF-8 跨帧正常且分别回放；首字节先录后转发；录制未就绪拒绝进入；中途写盘失败停止输入并关闭/冻结；乱序、重传、断流无缺口伪装；会话 token 单用绑定身份；隐藏密码输入不进入原始按键日志；非法查看/导出拒绝。

### P3：真实私网健康、数据优先与公网回退

交付：每 30 秒/3 秒超时业务 HTTPS 私网探测，连续 3 败降级、连续成功与稳定期恢复；指标/文件/PTY 按策略走独立数据通道。

验收：停掉测试 EasyTier 后公网控制不掉、授权 Exec 仍可用；私网连接绑定预期虚拟 IP 并校验 TLS/服务身份，拒绝重定向/DNS 回公网导致假健康；实际传输失败可立即仅对本次降级；小文件低频指标可回退、大文件受配额约束；VPN 恢复无反复抖动；默认路由被 VPN 接管时揭示公网依赖并拒绝声称具备独立恢复通道；公网 PTY 仍强制录像。真实 EasyTier 重启仅在授权的测试服务/设备上验证。

### P4：业务模板、文件、分组、批次与定时任务

交付：模板版本和参数校验；SHA-256 文件传输/续传；部门和设备授权；1 台金丝雀、每批 5 台；定时计划、失败详情、审计查询及告警。

验收：业务用户不能构造任意 shell/UID/路径；跨部门任务/结果/文件访问拒绝；文件损坏和路径穿越拒绝；金丝雀失败不放行后批；冻结本次目标清单避免执行中分组漂移；调度重启不重复生成同一 occurrence；时区/DST、漏跑、离线 TTL 策略明确；取消尚未开始与正在运行设备分别显示；50 台测试演练记录实际资源/流量和离线恢复结果。

### P5：可选连接器与上线验证

按需交付 SSH Proxy、签名 Agent 更新/回滚、对象存储、PostgreSQL 适配，不能把全部选项当成本期必做。

验收：启用 SSH 时代理终止 SSH 并真实录制，普通 TCP 转发不算录像；升级签名失败/版本回退/掉电恢复验证；50–500 台按实际工作负载压测，给出延迟、磁盘、带宽、重连洪峰数据；备份恢复、撤销、RBAC、许可证/SBOM、审计保护与安全审查完成。没有测试结果前不标“生产级”或“高可用”。

## 哪些直接实施，哪些需要确认

**普通实现决策，可在授权开发环境内继续：** 六项 ADR 的代码/协议落地；目录、数据库迁移、固定状态机、事务边界、序号、幂等键、低权限执行接口、默认拒绝/资源限制、开发证书和故障测试。确切数值作为有文档的配置默认值，不反复要求用户批准每个字段。

**需确认后再实际执行/变更：** 真实设备安装、服务重启、系统账号/权限和特权启动器部署、sudoers/polkit/cgroup 授权、公司身份系统授权；生产数据保留/删除政策；新费用/公网大流量；改变技术栈或把审计扩展到平台外；启用可选 SSH 或高权限维修动作。已有文档允许设计这些能力，不等于授权现在对生产动手。

**需要业务决定但不阻塞本地 P0/P1：** 首批测试设备/支持发行版和架构、正式域名/证书、公司身份来源、角色设备范围、输出及录像保留期/容量/公网预算。未知时只交付安全本地默认与待填配置，不编造生产参数。
