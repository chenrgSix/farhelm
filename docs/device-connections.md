# SSH 与 Agent 接入

管理员在设备页点击「添加设备」，再选择「SSH 接入」或「Agent 接入」，两种方式均使用弹窗表单。SSH 方式填写连接配置；Agent 方式填写安装信息并生成一条命令，复制到目标 Linux 执行后自动安装、注册并启动，详情见 [Agent 一键安装](agent-installation.md)。已有 Agent 设备可直接添加备用 SSH，保持同一个设备 ID、设备组、授权、身份与历史，不创建第二台设备。独立 SSH 设备仍可用于没有安装 Agent 的机器。两种设备共用网页终端、平台 SSH 入口、设备范围授权、会话额度、录制、时长、回放和导出。

```text
浏览器 / SSH 客户端 → 平台（认证、授权、录制） → WSS → Agent PTY
                                           → SSH → 目标 sshd / Shell
```

## 配置 SSH 设备

1. 点击「添加设备」→「SSH 接入」，填写名称、目标地址、端口、Linux 账号和私钥。平台服务端必须能访问该地址；`localhost` 指平台所在机器。
2. 目标账号的 `authorized_keys` 中配置对应公钥。粘贴 OpenSSH/PEM 私钥；加密私钥同时填写口令。目标端目前使用公钥认证，未开放目标密码认证、ssh-agent 转发或跳板链。
3. 点击「获取主机指纹」，与目标机器管理员提供的指纹核对后勾选确认；也可直接填写已知 SHA256 指纹。获取只读取主机公钥，在认证前断开，不提交登录凭据。扫描结果本身不证明主机可信，仍需核对。
4. 保存后点击「测试已保存连接」，验证网络、主机指纹和密钥认证；测试不创建 Shell、不执行命令。关闭面板后点击「连接终端」。

目标无需安装 Agent。SSH 客户端仍使用平台账号密码，例如 `ssh -tt -p 2222 -l admin 127.0.0.1`；菜单显示「SSH · 按需连接」。也支持 `平台用户名:设备ID` 直接连接。目标地址与私钥由平台使用，无需分发给操作人。

Agent 在线只代表 WSS 连接；SSH 不维持常驻连接，显示按需连接及上次检查/连接结果，不把历史成功当作实时在线。SSH 设备本版支持交互终端；持久化命令任务及 HTTP/TCP/systemd 健康检查仍要求 Agent，前端隐藏对应入口，服务端明确拒绝。

修改接入配置前需结束设备的活跃终端；revision 防止覆盖他人的修改。私钥留空保留原值；替换私钥时清除旧口令，必要时重新填写。主机指纹不一致会在认证前拒绝连接，不会自动接受新指纹。

## 为已有 SSH 设备安装 Agent

管理员在 SSH 设备行点击「安装 Agent」，填写运行账号、启动方式和有效期，生成命令并在该设备上执行。设备名称只读，平台地址自动带入。命令绑定原设备 ID，不通过名称或 IP 猜测设备归属，也不会新增设备。

生成命令、下载失败、注册未完成或 Agent 尚未上线时，设备仍使用原 SSH。只有 Agent 证明持有注册密钥并发送有效上线消息后，平台才将其设为 Agent 设备，保留原 SSH 地址、账号、私钥、主机指纹及配置版本作为备用；设备组标签、用户/用户组授权、历史任务和录制仍属于同一 ID。已打开的 SSH 会话继续运行，新会话按 Agent 优先规则选择通道。

命令过期且尚未注册时可重新生成，新的命令会使该设备之前未使用的安装命令失效。已注册但未上线时，请检查并启动目标 Agent 服务，无需重复安装；原身份在平台重启及命令过期后仍有效。安装需要目标 root 或 sudo 权限，平台不会自动通过 SSH 执行命令。详见 [安装与维护](agent-installation.md)。

## 为 Agent 配置备用 SSH

管理员打开「设备总览 → 接入配置」，勾选「启用备用 SSH」，填写目标地址、端口、账号、私钥及主机指纹，保存并测试连接。步骤与独立 SSH 设备相同；sudo 密码与 SSH 凭据分别维护。取消勾选并保存会删除备用 SSH 配置、私钥和口令，保留 Agent 身份及 sudo 密码。

网页终端、平台 SSH 入口的直连和设备选择菜单使用同一规则：新会话创建时，Agent 已连接、心跳有效且支持交互终端则优先使用 Agent；否则，有备用配置时尝试 SSH，没有配置则提示 Agent 离线或需更新。SSH 主机指纹不匹配、认证失败或连接失败会明确报错，不忽略指纹或改用未经配置的目标。SSH 仍为按需连接，配置存在不代表目标实时可达。

会话创建后固定通道。Agent 掉线会结束原 Agent 会话，重新连接才尝试备用 SSH；Agent 恢复后新会话重新优先使用 Agent，已打开的 SSH 会话继续使用 SSH。不会迁移 Shell、重放按键或恢复原工作目录。终端窗口和历史记录显示实际通道，两个通道共用同一设备范围、角色权限、额度、撤销规则和录制流程；SSH 使用配置的目标账号，其 Linux 权限可能与 Agent 运行账号不同。

设备仍是 Agent 设备，继续支持健康检查、网络记录、命令任务和升级。这些功能不自动转由 SSH 执行；Agent 升级期间对新 Agent 终端的限制仍有效，Agent 不可用时备用 SSH 可用于排查恢复，不受未确认升级批次阻塞。

接口沿用 `PUT /api/v1/devices/:id/connection`：Agent 可以同时提交 `ssh`、`private_key`、`passphrase` 和 `sudo_password`。省略字段保留已有值，`ssh:null` 仅允许 Agent 设备明确删除备用配置；所有变更均要求管理员、最新 revision 且设备没有活跃会话。`connection_kind` 保留 `agent`，设备列表新增 `ssh_configured` 和当前预计使用的 `terminal_backend`。无需数据库迁移或重装 Agent，已有 Agent / SSH 设备保持原有行为。

## Agent 可选 sudo 密码

Agent 设备的「接入配置」可设置、替换或明确清除 sudo 密码。留空保留原值；没有配置也不影响 Agent 连接和普通终端。

仅管理员可配置，任何角色（包括管理员）都不能通过 API 读回明文。「以 root 连接」或兼容账号选择 sudo 切换时，会由平台代用此密码；免密 sudo 不需要保存密码（Agent 0.2.9+）。普通终端不会自动提权，Linux sudoers 不会被改写。原有 Shell 内手动 sudo 仍遵循目标系统权限。

## 凭据与录制

- 私钥、私钥口令和 sudo 密码使用 AES-256-GCM 保存，每次随机 nonce，以设备 ID 绑定 AAD。配置响应只有 `has_*` 标志，设备列表和审计不包含明文。
- 数据目录的 `credentials.key` 是独立 32 字节密钥，权限 0600。备份恢复须保留原密钥，建议与数据库备份分开保护。已有凭据时缺少密钥会阻止启动，不自动生成替代密钥。此加密不抵御平台主机与密钥一并失陷。
- 设备终端授权允许平台代用已保存的 SSH 私钥建立连接，不等于可查看私钥；配置权限与终端使用权限分开检查。
- 录制只保存 PTY 输出，不保存原始按键；终端回显仍会录制。SSH 输出与 Agent 共用 SQLite 提交后再转发的流程，录制失败会断开。上游入口 `transport` 与下游接入 `backend` 分别保存，历史会话默认 `backend=agent`。
- 目标 SSH 的 exit 通知表示 Shell 正常结束，异常网络断线标为中断。主动结束会话关闭 SSH 连接；不保证已脱离终端的后台进程全部退出。

## 本地验证

服务端测试使用真实 SSH 协议测试端验证凭据、指纹、权限、录制与原有 Agent 路径。真实 Linux 验证使用独立 OpenSSH 容器，不修改现有 Agent 容器：

```bash
docker build -t farhelm-sshd-test:local tests/e2e/ssh-target
npm --prefix apps/server run build
npm --prefix apps/web run build
npm run test:ssh:target
npm run test:ssh:backup # 同一个已存在的 Agent 设备配置备用 SSH
```

脚本使用临时凭据、数据库及仅绑定宿主 loopback 的 sshd，验证浏览器配置、桌面/手机布局、真实 Linux PTY、Ctrl-C、resize、中文、隐藏输入、录制回放和系统 OpenSSH 经平台菜单连接，结束后移除测试容器。Chromium 可用 `PLAYWRIGHT_BROWSERS_PATH` 或 `FLEET_CHROMIUM_BIN` 指定。结果位于 `.test-output/dual-access-*`，不等于 CI 或生产验收。

双通道服务端测试覆盖 Agent 优先、离线/心跳过期/不支持终端时回退、恢复后保留已有 SSH 会话、主机指纹失败、同设备权限与撤销、凭据删除和原 ID 不变。其中 Agent 使用协议测试端，SSH 使用真实 SSH 协议端；`test:ssh:backup` 另以真实 Linux OpenSSH 验证备用 SSH 的前端配置、网页终端、平台 SSH 菜单、录制和回放。

## 目标账号与登录／切换方式

管理员在设备「更多 → 高级账号（兼容）」中管理默认账号及附加账号的登录身份、方式和凭据。默认账号沿用原接入配置；附加账号支持直接 SSH 或 Agent sudo 切换。谁可以使用账号统一在「访问控制 → 高级授权 → 访问授权」配置，并可在「权限核对」查看生效来源。已有配置和授权保留，默认账号也纳入同一授权检查，详见[访问控制体系与兼容规则](access-control.md)。用户仍须具备设备范围、终端连接及对应的特权操作权限；凭据只允许平台代用，不返回浏览器。
- **直接 SSH 登录**：使用本账号的用户名与私钥，地址、端口、主机指纹及内网策略沿用设备的 SSH 接入配置。可用于 root 或普通账号；目标必须允许对应的密钥登录。账号编辑时私钥留空保留原值，更换私钥会清除旧私钥口令。
- **sudo 切换**：Agent 仍以普通账号运行，平台请求从该账号经 sudo 切换至目标账号。可以填写本账号专用的源账号 sudo 密码，也可留空使用设备接入配置中已保存的 sudo 密码。需要 Agent **0.2.8+**、`FLEET_TERMINAL_ALLOW_PRIVILEGE_ESCALATION=1`，以及目标机器已配置的 sudo 授权。此方式不自动修改 sudoers，不支持从另一个 SSH 登录账号发起 sudo。

网页直接提供「连接终端」与「以 root 连接」，日常只需设备授权和角色中的 sudo／root 权限；原有精确规则继续生效。需要指定旧账号时使用「更多 → 选择已有账号（高级）」。平台 SSH 先选设备，再选可用的普通／root 方式（只有一种时直接连接），也保留已有高级账号；默认账号不能绕过已撤销的授权。

账号配置及删除使用版本校验，设备存在活跃终端时拒绝修改。连接创建、附着、输入、输出和定时检查均重新校验账号 ACL、当前角色与设备范围；撤销访问后会结束会话。选择的账号 ID、用户名和方式写入初始录制事件与会话创建／打开审计。SSH 和网页共用这一流程，不允许提权失败后退回默认账号。

密码通过已认证的 Agent WSS 通道仅交给本次 sudo 会话；Agent 使用会话专属的 Unix socket 为 sudo askpass 提供密码，核对请求进程属于本次启动的 sudo 进程树，并验证目标账号身份后才开放终端。密码不经过浏览器、PTY 输入、命令参数或环境变量。sudo 密码错误、权限不符、旧 Agent 或认证超时均明确失败。录制继续只保存终端输出。

账号和源账号须已存在于目标机器；平台账号配置不会在 Linux 上创建用户。sudo 会话可切换至 root，但 Agent 自身与命令任务仍保持普通账号及原有执行限制。拥有 root Shell 的用户拥有目标系统的 root 权限，此功能不是目标系统内的沙箱。

验证：`npm run test:target-accounts` 在独立 Linux 容器中使用真实 Agent 和 sudo，覆盖网页终端协议、SSH 两级菜单、实际 root 身份、错误密码拒绝，以及密码不出现在录制和审计。需要先构建 Linux Agent，默认读取 `.dev/linux-target/debug/farhelm-agent`，可用 `FLEET_AGENT_BIN` 指定；测试镜像默认 `farhelm-agent-dev:local`。不修改已有部署。
