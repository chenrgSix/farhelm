# Agent 本机 IP 与连接中断记录

Agent 0.2.2 起自动启用，无需额外权限或配置。设备列表显示第一个上报的 IP，可按所有上报 IP 搜索；点击设备的「网络记录」查看各网卡 IPv4 / IPv6、网卡启用状态和连接中断历史。仅 SSH 接入的设备不采集这些数据。

## 网络探测配置与故障判断（Agent 0.2.3 起）

进入「设备总览 → 网络记录 → 网络连通性探测 → 探测配置」。管理员或有该设备操作权限的运维可以编辑；业务、审计用户只可查看授权设备。各设备单独配置，保存会记录操作审计。

- 默认停用，尚未填写目标时不主动探测外部地址。启用时需要 2–5 个目标，建议覆盖网关以及不同网络中的外部地址。两个目标落在同一主机或同一故障域不能提供独立证据。
- 地址支持 `http://`、`https://` 和 `tcp://主机:端口`，可使用域名、IPv4 或 IPv6。IPv6 URL 使用方括号，例如 `tcp://[2001:db8::1]:443`。拒绝 URL 账号密码、片段、无效端口和重复目标。
- 探测间隔为 5–3600 秒，默认 30 秒；每轮完成后等待此间隔。单目标超时为 100–10000 毫秒，不能大于间隔；默认 3000 毫秒。连续失败阈值为 1–10 次，默认 3 次。各目标并发执行，超时或配置替换会取消旧探测。
- TCP 成功建连表示可达。HTTP 收到任意响应状态（包括 4xx / 5xx）表示可达，不读取正文、不跟随重定向、不使用环境代理，也不携带平台认证信息。HTTPS 正常验证证书，兼容 Agent 已配置的 CA。业务是否正常仍由「健康检查」判断。

| 当时的探测结果 | 判定 |
| --- | --- |
| 平台在线，所有目标可达 | 网络探测正常 |
| 平台失联，所有目标可达 | 平台连接异常，其他目标可达 |
| 只有部分目标不可达 | 部分探测目标不可达，仍有网络连接证据 |
| 所有目标失败但尚未达到连续次数 | 等待连续确认 |
| 连续失败达到阈值，平台仍在线 | 探测目标异常，平台仍可达 |
| 连续失败达到阈值，平台也失联 | 疑似网络故障：所有目标均不可达 |

有限数量的探测不能证明整机完全断网。DNS、防火墙、TLS 配置或目标自身异常也可能使全部探测失败。界面保留逐目标的地址、结果、失败类别和耗时，并显示当时的平台连接状态及配置版本，供核对。主动升级或地址切换期间不据此产生故障判断。

配置保存到平台后显示待确认；支持的在线 Agent 持久保存后回执，离线设备重连自动接收。新配置有独立版本，拒绝覆盖其他人刚保存的版本。Agent 的探测任务独立于平台连接和重连等待，断线或重启后继续使用最后已接收的本地配置；离线期间在前端修改的配置须等重连后才生效。

每轮保存最近结果，仅在分类、逐目标结果或配置版本变化时追加历史证据。Agent 使用持久递增序号，未确认记录逐条重传，平台提交后确认并去重；平台保留旧配置版本以校验延迟补传。当前结果和历史队列分开，补传不会覆盖较新的当前结果。离线、配置已替换、连接已重建但尚无新结果或结果过期时，只显示历史参考。

协议能力 `agent.network.probes.v1`，接口 `GET/PUT /api/v1/devices/:id/network-probes`；新协议与原 IP / 连接中断记录独立，旧 Agent 仍可正常使用原功能。升级到 0.2.3 后再启用探测。服务器保存配置历史和证据；本地已确认历史保留最近 1,000 条，未确认记录不自动删除。

## 采集与时间含义

- 每次连接以及每 30 秒通过 `getifaddrs` 读取本机网卡，排除回环接口。包括容器、虚拟网卡和 IPv6 链路本地地址；不请求公网 IP 查询服务。IPv6 链路本地地址所属的网卡单独显示。最多上报 128 个地址，超限明确提示。离线时保留最后一次采集结果和采集时间，不当作实时数据。
- Agent 每 5 秒通过已认证的控制连接发出 WebSocket Ping；只接受匹配的 Pong。最后响应后 20 秒未收到确认，主动断开并记录检测时间。外层超时也覆盖阻塞的 socket 写入。连接关闭或失败时可更早检测到。
- 「与平台断连」只说明 Agent 与平台之间的连接中断。平台重启、网络故障、防火墙或认证异常都可能导致它，不能据此确认整机断网。
- 「连接平台失败」表示启动或主动迁移后未能建立连接。「Agent 进程中断」表示上一次运行曾在线，本次启动无法确认何时停止；界面将持续时间标为「起点未知」。主动升级及成功切换平台地址不计为断网。
- 事件包含最后确认连接、检测、恢复时间；恢复时间取重新完成平台身份确认的时间。检测时间不是物理断网的精确起点。日期使用 Agent 本机时钟，前端按浏览器本地时区显示；持续时间为检测到恢复的时间差，时钟回拨时最小为零。建议正常维护设备时钟。

## 持久化与查看

断线时平台无法立即收到 Agent 的记录，因此先写入 Agent 状态目录的 `journal.sqlite3`（`network_state` 元数据及 `network_events` 表），与原身份、任务状态共用 SQLite WAL / FULL 同步保障。重启后沿用未恢复事件的 ID 和原检测时间；重复失败不会重置起点。

重连后每秒补传一条已恢复事件；平台持久提交后按事件 ID 回 ACK。丢失 ACK 会重传，平台按设备 + 事件 ID 去重，拒绝篡改已确认事件。同一设备的未确认记录不自动删除，已确认的本地记录保留最近 1,000 条。平台历史持久保存，每页 50 条，按接收顺序查看更早记录。

离线时界面显示平台最后心跳并提示等待补传；不能凭最后心跳伪造 Agent 检测时间。设备授权范围适用于查询接口，业务、审计用户可查看已授权设备；没有新增密码、sudo 或执行权限。

协议：能力 `agent.network.v1`；`agent.network` 上报地址，`agent.network.event` 补传已恢复事件，`agent.network.ack` 确认持久化。查询 `GET /api/v1/devices/:id/network[?before=<sequence>]`，参见 `contracts/v1/agent-network-envelope.schema.json` 和 `device-network-response.schema.json`。新 Agent 与旧服务端连接时仍保留本地记录，升级服务端后补传。
